# 林中别墅末日堡垒 工作流

## 剧集生成前

1. 阅读本故事 `AGENTS.md` 和 `docs/production-rules.md`。
2. 检查上一集 `continuity.md`，确认物资、伤口、门窗、灯光和丧尸位置。
3. 确认本集只做一个核心生存任务。
4. 确认数字人资产 ID 是否需要写入 `api-request.md`。
5. EP041–EP050读取当前 `ep041-050-rebuild-outline.md`，不要再引用旧大纲的凑字数、逐小节拍口播规则。

## 台词与剧情重构

- 先列出本集开始时各人知道什么、缺什么、想做什么；没有看到或听到的事不能直接说成事实。
- 先写连贯场景再分镜，不以四格模板强行让四个人各念一句。
- 30秒段拆成至少8个实际镜头，15秒段默认4镜头。先串起起因、动作、反应、结果，再安排对白；不能靠增加话量凑满镜头。
- 逐镜检查“这一镜结束后有什么发生变化”。固定机位可以使用，但被摄主体要有可见动作或状态变化；没有叙事作用的重复推拉、站立口播不计作有效补镜。
- 每个主要决定都应改变下一镜的处境：选择、尝试、结果、代价至少可见，不靠解释词堆积推进。
- 独立通读对白：每句对谁说、回应什么、是否像此人，会不会靠前文才能猜出主语。读不明白就重写整轮交流，不只换同义词。
- 通读时隐藏画面说明，只保留按镜头顺序排列的台词。观众仍应听出这一段在争什么、谁改变了想法；若只能听见八条工作汇报，即使每镜有声也不得通过。
- 危机戏与日常戏分别处理。从EP042起新写或重写的镜头，逐镜核对至少一句具名对白；纯道具、背影和远景镜头标明现场画外音来源，不能把声音配给画面里错误的人。每镜说完仍要给动作、停顿与反应留时间，逐段统计总字数并通读30秒语速。
- 统一更新episode、storyboard、director-promt、prompt、首尾状态、连续性和API交接；不能只改概述不改真正提交的导演稿。

## 资产生成前

- 人物优先使用火山 Ark 数字人资产 ID。
- 场景资产优先补：林中别墅外观、室内仓储、地下室、发电机棚、山路、后院菜地。
- 首尾帧必须让观众看懂空间变化，不只做氛围图。

## 视频提交前

- `director-promt.txt` 只写导演指令，不写本地路径、不写密钥、不写 signed URL。
- `api-request.md` 写清模型、数字人资产 ID、首尾帧、场景图和参考图上传计划。
- 默认使用低成本模型草稿，动作逻辑稳定后再定稿。
- 本地30秒剧本不等于模型支持30秒；必须核实真实服务端参数，不能照旧文档里未经核实的名称提交。
- 新剧情改变人物、动作或设备后，把旧参考图标为待复核。目录有图片不等于覆盖新稿，更不等于已提交。
- 提交前回读实际director-promt.txt的逐镜标题，确认30秒段不少于8镜；从EP042起逐镜验证至少一句实际发声对白与明确说话者，核对storyboard、episode台词表与prompt副本一致；不拿参考图张数代替镜头数。
