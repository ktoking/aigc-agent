## 3. 故事、人物与空间锁定

### 故事卖点和语气

夜班理货员在闭店后的丧尸爆发中封闭卸货入口，依靠超市物资建立临时住处；拒绝被咬的店长入内后，与冷链维保技师许棠逐步建立信任，共同在山姆生活。

第一人称讲故事，具体、自然，带一点打工人幽默。通过装满的购物车、整排饮用水、床、两套餐具、交班和记账兑现资源优势。不反复宣称无敌，不用冗长解释代替画面。

“第一人称”指叙事信息来源；镜头可以从外部拍主角，但不能呈现他不知道的幕后事实。监控内容必须能解释为他看见的信息。

### 角色卡

- 仓储卖场：高工业屋顶、蓝立柱橘横梁、成箱商品、宽通道；构图保留纵深，不能每个镜头换成另一家店。

- 入场路线：室外装卸区 → 外卷帘门 → 带窗收货缓冲间 → 内门 → 卖场和监控室。白色维修车在装卸区室外。画出生产用关系图，图中标注不进入故事镜头。

- EP006：第二天傍晚，观察约一日后进入、共同吃饭、交付监控室钥匙。

## 4. 画风与逐张生图提示词

### 统一画风

横屏 16:9，干净彩色二维生存漫画。人物轮廓清楚、黑色描线稳定、大色块和适量赛璐璐阴影；环境有可读的货架、包装、设备和空间层次，细节适中。角色温暖，仓库偏冷蓝；不是整幅暖黄滤镜。保持适合视频观看的主体尺寸和注意力锚点。

禁止过度锐化、鱼鳞状网格、满屏微纹理、密集乱码标签、过量细节、拼格、分镜表、字幕、对白框、二维码、水印、可读品牌标志、黑边、真人、三维渲染、服装漂移、肢体畸形、空间跳变和血腥特写。

### 参考图使用

若附带参考图包，先读取 `references/manifest.json` 并逐图查看：

- `references/style-and-hero.png`：主角、服装、仓储卖场及整体画风。
- `references/xu-tang.png`：仅锁许棠的脸、发型、服装、工具包，不继承背景开门状态。
- `references/manager-on-monitor.png`：店长外貌和监控呈现；不要把显示器边框带进直接室外镜头。

## 6. 分镜和时间线编排

- 先用附录锁定每集四个15秒叙事段落。画面每3—5秒有信息、构图或注意力变化；不靠每秒闪切制造节奏。
- 开头5秒兑现题材或承接上集悬念；单集只解决一个核心任务，结尾形成具体问题或情绪落点。已经锁定的温馨落点不用强加新反派。
- 段落可以通过明确跳切进入新场景。首尾帧“承接”指时间、人物和空间能解释，不强行要求所有跳切画面像素一致；记录转场理由。
- EP001 采用附录的13镜头时间表。若没有原图，按附录11个事件图重制。
- EP002—EP008 每段两张事件图，可按以下局部时间分配：0—4秒第一张全景，4—7.5秒第一张局部，7.5—11.5秒第二张全景，11.5—15秒第二张局部。局部要服务注意力，避免切掉关键伤口、钥匙或门边界。
- 缓推、缓拉、轻微横移为主，通常缩放约1.02→1.07，局部特写约1.10→1.14；需要时按实际图调整。每镜头不必同时推拉与横移。安全裁切，不露出画布边缘。
- 转场参考6帧叠化，即30fps下0.2秒；涉及不兼容空间可用清楚跳切。叠化必须通过重叠或渲染合成处理，不得让总时长因转场减少，也不能在0.2秒叠化中出现明显双脸。
- 所有时间线用整数帧管理：每集1800帧，每段450帧。总片14400帧，不能把标称时长当作帧数证据。
- 保存 JSON 时间线，至少包括源图、起止帧、缩放/位移、过渡、字幕时间和文本。另保存实际可运行的渲染源或脚本。

建议分阶段完成：先用EP001的一个15秒段验证图片读取、运镜、叠化、编码和时长，再渲染EP001整集；检查通过后逐集推进。小样复用正式素材，不额外调用视频生成服务。

## 7. 无声视频与独立字幕

- 最终MP4仅有一条H.264视频流，1920×1080、恒定30fps、yuv420p；每集1800帧/60秒，合集14400帧/480秒。适合浏览器播放，启用faststart。
- 禁止配音、音乐、环境声、音效；即使剧情提到撞门、报警、发电机，交付也完全无音轨。不是静音音轨，而是音频流数为0。
- 禁止画面烧录字幕、片头大字、姓名条或解释性文字；第一人称文案通过独立UTF-8 SRT交付。发布封面文案可另写在文档中。
- 不把SRT封装进MP4；MP4内部字幕流数也为0。外挂字幕提供浏览器用VTT副本，内容与SRT一致。
- 字幕按人工阅读节奏排时，不叫音频逐字对齐。按四段分配文本，长句优先在标点处拆成最多两行，避免遮挡关键信息。
- 默认一条原稿正文行对应一个cue，条内可换行；按字数及语义在对应15秒内分时，起止帧单调、无负时长、无非预期重叠、不越界。阅读压力大时按标点拆cue，正文仍须逐字一致；记录最终cue数。
- 原版参考：EP001 18条字幕，EP002—EP008共112条，合集130条；本轮以实际字幕排时为准，不为了凑数量删字或压缩阅读时间。
- 自动核对：按顺序拼接SRT正文，去掉展示换行和空白后，与附录原稿正文去空白后的字词、标点完全一致。画面说明、标题、分镜标签不得混入。

如果采用FFmpeg，请根据当前实际版本实现并验证命令。不要直接拼接未经验证的伪命令。使用参数数组调用subprocess，避免shell引号问题；路径相对于工作区。渲染后可按实际文件去音频、去字幕流：

```bash
ffmpeg -v error -y -i INPUT.mp4 -map 0:v:0 -c:v copy -an -sn -dn -movflags +faststart OUTPUT.mp4
```

确保INPUT和OUTPUT不是同一个文件。保留原始渲染来源及本轮运行标识，不把旧raw视频误当新构建结果。

## 8. 合集、播放器与交付

1. 八集按001至008顺序连接，不额外加片头片尾或黑场；严格保持480秒。统一编码参数，验证兼容后可无损concat；不兼容才重编码，并复查总帧数。
2. 第n集字幕整体偏移 `(n-1)*60秒`，重新连续编号；不能只拼SRT文件文本。检查第60、120、180、240、300、360、420秒附近的字幕和画面。
3. 生成 `chapters.json`，记录标题、起点和单集路径。
4. 播放器用HTML video和外部VTT track，可开关字幕、跳转章节。确保视频和字幕通过实际可访问的相对URL加载；需要时运行工作区HTTP服务，不把file协议下的失败当成字幕损坏。
5. `publish-package.md` 每集提供至少3个标题、封面构图、封面文案建议、简介、评论引导和标签；仅生成发布素材，不执行发布。
6. 交付manifest记录最终文件相对路径、字节数、SHA256、视频参数、cue数和本轮验收状态。按云端平台可用方式提供下载链接，必要时打包交付。

## 附录D：替换题材时的使用方式

用户另给题材时，将第1节mode改为new-story，提供新的story_id、题材、集数和正文来源。沿用能力预检→故事建模→资产锁→剧本→分镜→逐图prompt→生图复核→静帧剪辑→独立字幕→合集→实际验收的流程；删除本剧角色、空间、库存和附录A—C的剧情锁，禁止把它们混入新剧。新剧本未提供时先写入drafts，按用户授权范围推进；保留用户对剧本的审阅要求。不要因为复用流程擅自变更画幅、音轨或字幕交付规格。
