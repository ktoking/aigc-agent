# 原版与用户抖音剪辑版：节奏对照及v2变更

核对日期：2026-10-18。本次仅分析、更新流程和字幕估算稿，没有重渲染视频或生成配音。

## 结论

原版对于用户后期加速叙述的用途，句子占用时间明显偏长。问题并非原SRT有空白间隔：原18条cue连续覆盖0—60秒，句间空白为0。问题是按固定60秒、四段各15秒安排画面，把短句也拖长；用户的语音读完后，剩余画面时间就会成为等待。仅将字幕结束延长到下一句，不能解决这个问题。

原版EP001为192个非标点中文字符/60秒，整体3.2字/秒；不同句子的密度从2.0到5.0字/秒，短句受到的拖慢尤为明显。原后续脚本按`len(text)+4`分配固定15秒，也会对短句产生额外时长权重。

v2改为：先按正文累计字数计算连续帧边界，再让镜头、段落、单集与合集读取同一时间线。句间加时、标点加时、片头等待、段尾补时、片尾等待均为0。不生成配音，用户后期控制实际语音和倍速。

## 参考视频的实际读取

- 用户分享链接：`https://v.douyin.com/yFZ66-ODfqE/`。
- 解析与页面核对：`https://www.douyin.com/video/7697276135230486848`，作者“凯哥”，作品《丧尸爆发后 我住进了整座山姆》。
- 浏览器视频元素时长42.233333秒，播放速度1；通过页面实际视频元素下载，ffprobe亦读到42.233333秒、1267帧、30fps、1280×720、HEVC视频和AAC音频。
- 旧版为60秒；参考版短17.766667秒，即缩短约29.61%。这不等于已证明每句都按同一倍率加速。
- 以5fps抽取211张底部画面，使用macOS Vision OCR，将识别文本匹配到原18句；另查看每秒画面拼图和疑似漏字区间。证据保存在本目录。
- 可匹配15句，共168个非标点字符；其抽样显示区间约33.2秒，约5.06字/秒。边界误差约0.2秒，适合作为估算基准，不是精确逐帧字幕轨或发音速度测量。
- 原第13句“第一次，没看价签。”、第14句“我把露营床搬进监控室，铺好被子。”、第17句“是店长。”未在抽样画面中观察到。实际查看床镜头抽帧未见该句字幕。不据此断言音轨没有说这些话，v2仍保留三句全部原文。
- 已匹配字幕之间也能观察到约0.2—0.6秒的无字区间；这只能说明字幕空档，不能当成已检测的声学静音。用户要求取消间隙，因此v2借鉴字速，不复制参考版的这些间隙。
- 没有执行ASR、语音活动检测或音频终点对齐；声音是否逐句紧接属于NOT_RUN。没有凭字幕或AAC音轨存在推断音频内容。

## 从旧版改到v2

| 项目 | 旧版流程 | v2流程 |
| --- | --- | --- |
| 计时顺序 | 先定60秒/15秒，再分字幕和镜头 | 先估计台词时长，镜头与字幕读取同一时间线 |
| 基准速度 | EP001整体3.2字/秒，短句更慢 | 默认5.0个非标点字/秒，可调 |
| 句尾停顿 | 没有SRT空白，但不少句子占时偏长 | 不添加任何默认停顿帧 |
| 句间/段间/集间 | 固定段落时长及60秒偏移 | 共享帧边界，空档与重叠均0帧 |
| 转场 | 常用6帧叠化 | 按需要跳切或2—4帧叠化，在既有时长内完成 |
| 单集时长 | 全部60秒 | 各集由完整正文和cps计算 |
| 合集 | 480秒，字幕每集偏移60秒 | 按新单集真实帧数累加 |
| 配音 | 未生成 | 仍不生成，用户后期自行处理 |
| 字幕性质 | 人工阅读节奏 | 连续叙述节奏估算稿，尚未与未来语音对齐 |

## 验收边界

- 已验证：下载参考视频元数据；15句可观察字幕显示区间与192字原稿的对照；八集正文未改；130条新单集/合集字幕边界连续；合集偏移使用实际帧数；ZIP完整性。
- 未执行：v2视频渲染、未来配音生成、声学停顿检查、语音逐字对齐、新视频浏览器播放验收。
- 参考的字速用来设估算参数。未来实际音频如与估算不一致，需要按真实语音时间重排字幕和镜头，不能将本轮字数估算当成已证明说话无空档。
