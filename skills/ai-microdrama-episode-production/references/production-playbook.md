# 短剧制作沉淀

## 制作大师视角

短剧不是把长故事切碎，而是在每 3-5 秒给观众一个继续看的理由。AI 短剧还多一层约束：每个画面都要服务于资产稳定。先锁资产，再讲情绪；先做连续性，再做炫技。

## Story 包结构

每个 story 独立维护：

```text
stories/<story-id>/
  AGENTS.md
  README.md
  docs/
    story-memory.md
    production-rules.md
    workflow.md
    season-arc.md
    audience-strategy.md
  assets/
    characters/
    scenes/
    props/
    style/
  episodes/
```

公共层只沉淀方法，不写死具体人物、世界观、剧情。story-local `AGENTS.md` 和 docs 的优先级高于公共 skill。

## Story 建模框架

新 story 至少明确这些模型：

- **一句话卖点**：能让人立刻知道为什么要看。
- **世界规则**：观众需要理解的 1-3 条硬规则。
- **主角锁**：外观、能力、欲望、恐惧、语气、禁止变化。
- **阻力锁**：反派或系统的目标、手段、升级方式。
- **情绪引擎**：每集持续驱动观看的情绪，例如悬疑、爽点、救赎、荒诞、恐惧。
- **视觉锚点**：角色、场景、道具、特效、色彩、镜头语言。
- **负面提示词**：防止角色漂移、风格漂移、错误题材和生成伪影。

## Episode 结构模型

默认 60 秒四段：

- Segment 01：开场钩子和即时冲突。
- Segment 02：压力升级、选择、误会或计划。
- Segment 03：反转、爽点、揭示或能力展示。
- Segment 04：后果、情绪落点和下一集钩子。

扩展样片可增加到 8-10 段，但每段仍只承担一个戏剧任务。命名按真实时间段递增，例如 `segment_10_135-150s`。

## 首尾帧设计模型

首尾帧不是普通插图，它们是视频生成的锚点。

- 首帧：承接上一段尾帧，明确角色姿态、场景、道具、压力源。
- 尾帧：给下一段首帧留下明确状态变化、悬念或动作方向。
- 每张图必须写清角色锁、场景锁、道具锁、光线、构图、镜头、负面提示词。
- 同一段首尾帧之间要能解释为一个 15 秒以内的视频动作。
- 下一段首帧若跳切，必须写清可见转场理由。

## 画面生成策略

- 优先生成角色定稿、动作参考、场景参考，再生成剧集首尾帧。
- 对非人类主角，必须反复写清“不是人类、不是性感 android、不是重型机甲”等负面约束。
- 对重要面部/眼位/道具位置，写成正向锁 + 负面锁，避免生成模型左右漂移。
- 同一 story 每次生图都引用相同资产编号和参考图路径。
- 修正图时只修最关键错误，不要重新发明整张画面。

## 资产追踪经验

最近 robot-dream-ban / last-mile-robot 的制作暴露了一个高风险点：不同 story 的图片可能在 staging 或会话记录中混在一起。后续必须先建立 source mapping，再复制。

可靠证据顺序：

1. 用户明确给出的图片路径和画面。
2. 图片 hash 与用户指定源一致。
3. 生成 prompt 中有目标 story id、episode、segment、FIRST/LAST。
4. manifest 或 assigned-images 明确指向目标 story。
5. 视觉内容符合 story 锁。

低可信证据：

- 文件名像 `segment-01-first-frame.png` 但没有 story 归属。
- staging 目录名与当前项目相似。
- 只凭“最近生成过”判断。

## 最终交付检查

交付前必须做：

- 文件检查：每段 docs 和 `frames/first-frame.png` / `frames/last-frame.png` 是否存在。
- 数量检查：segment 数量 x 2 是否等于首尾帧数量。
- 尺寸检查：同一 episode 图片尺寸和画幅是否一致。
- Hash 检查：用户指定源图是否与目标落位文件一致。
- 视觉检查：打开 contact sheet 或逐张图确认无错 story、无明显角色漂移、无错误主体。
- 说明检查：最终回复说清楚复制了哪些、没做哪些、还有无缺口。

## 交付措辞

不要只说“已经生成”。要说明：

- 目标 episode 路径。
- 已落位的图片数量。
- 关键校验结果。
- 是否有未解决问题。

如果只生成了 prompt、frames、task JSON，而没有 `.mp4/.mov/.webm`，不要说已经是剪辑软件可直接交付的视频库。
