# 小红书写作 Harness

把真实样本提炼成可复用规则，并把生成、主编反馈和版本记录连起来。本次用户方向、素材、文体与语气优先；Harness 提供参考，不把账号固定成批判、技术或任何其他领域。

## 内容来源

1. 已登录小红书 MCP 只读搜索，最多4个领域关键词。快速更新使用平台图文/半年内/最多点赞筛选；深入采样读取普通搜索结果，本地筛图文和点赞、排序，详情页核验发布时间。
2. 排除政治与明显转载，至少500赞；按领域交替读取，去重后最多50次详情请求；深入采样没有有效发布时间或不是图文的正文不计入。默认目标20篇完整正文，4篇适合快速更新，支持至30篇。
3. 点赞保留采样时间、原始显示值与是否约数。样本正文不足80字时跳过，不能把图片里的字当已读正文。模型最多看每篇2200字，超过时记录摘要输入范围。
4. 原文和访问token只在内存中。持久化只保留公开标题、笔记ID、无token链接、点赞、时间和读取范围。采样不是全站榜单，也不证明表达方式造成热度。

## 提炼内容

同一次本机官方 Codex CLI `gpt-6.1-sol / high` 调用，输出：

- 标题：具体对象、选择、成本或容易混淆的判断，避免空泛情绪词。
- 开头：进入具体问题、生活细节或观点，避免每篇相同的反转。
- 正文：细节怎样服务观点、如何安排解释与论证，不复制素材的立场。
- 收尾：停在具体判断或可用选择，不硬总结或求互动。
- 语气：自然、主观、客观、批判、犀利、温和、幽默、共情怎样组合使用。
- 写法模板：个人取舍、客观解释、规则批判、生活共情、轻松观察。每个学习模板至少有两篇真实依据。
- 首图建议：只放标题与短钩子，正文承担完整内容。未读取图片像素时不能宣称已经分析图片风格。
- 应避免的问题：套话、虚构亲历、替所有人下结论、刻意制造矛盾、机械照搬结构。

学习结果校验来源ID、长度、语气与规则数量，拒绝连续18字以上复用源正文的规则与示例；该检查是局部重复检查，不等于完整语义去重。原文里的任何指令都不能执行。学习只借结构和表达规律，新的观点、事实和例子围绕本次素材形成。

## 生成链路

填写方向与真实素材 → 组合语气 → 展示推荐写法与示例 → 冻结模板和Harness版本 → 同一次Codex调用生成标题、正文、短钩子 → 本地HTML/CSS通过Chrome渲染一张1080×1440封面 → 每篇完成即进入审核中心。

模板与Harness都在任务开始时固定。普通生成不重新读取平台；没有可用Harness时仍能用内置写法。模型在本次输出前自行检查重复套话、内容重点与虚构经历，不增加另一轮慢调用。不自动批准或提交。

## 本地记忆与反馈

- SQLite的`writing_templates`、`writing_harness`保存当前规则，审计保存完整版本快照。
- `data/writing-harness/current.md`供人阅读，`vN.md`与`vN.json`保留每次学习结果。生成任务也保留实际使用的版本与规则。
- `style_usage`记录哪个文章版本使用哪个模板版本，结合有效审核记录统计采用与过滤。
- 至少3次有效决定后，反馈轻微调整兼容语气的推荐次序。新版规则从新样本开始累计，不挪用旧版成绩。
- 真实发布指标通过已有采集入口读取，缺失保持未知。点赞只能作观察，暂未实现曝光校正、可信因果归因或自动多变量实验。
- 更新样本时重新提炼并保存新版本。接口立即返回，采集在后台；界面显示目标数、已读正文数与任务阶段。成功结果缓存6小时。

学习失败保留现有规则，不退回演示结果、不切换外部模型。平台读取期间让发布队列等待；读取结束释放平台资源。结果待核实的发布始终优先人工核实。

## 查看与操作

- 准备内容 → 选择语气 → 写法模板预览 → 查看公式与高赞样本。
- 展开“学习高赞写法” → 修改领域关键词 → 深入学习20篇，或快速更新4篇。
- `GET /api/writing/harness`读取当前Harness；`GET /api/writing/learning/latest`读取进度。
- `POST /api/writing/learn`：`{"keywords":["职场感悟","消费体验","生活感悟","周末生活"],"target_samples":20}`。

自然表达、原创质量可以改进；爆款表现与平台识别结果无法保证。
