# Codex 开发任务：XHS Growth Agent — AI 小红书内容运营系统

## 你的角色与最终目标

你是一名资深 AI Agent 架构师、全栈工程师、小红书内容运营总监、增长策略专家和视觉设计师。

现在需要你在我的 Mac 本地真正搭建一个可以持续运行的「XHS Growth Agent」。

这不是演示项目，也不是只生成几个 Python 脚本，而是具有完整内容生产、选题研究、热点追踪、图文设计、人工审核、发布管理、数据分析和策略优化能力的实际产品。

使用 OpenAI Codex 进行开发，并通过以下开源 MCP 对接小红书：

https://github.com/xpzouying/xiaohongshu-mcp

核心目标：

- 每日自动研究至少 100 个候选选题。
- 每日筛选出 50 个具有潜力的原创选题。
- 每日具备生成 50 篇完整图文笔记的生产能力。
- 自动完成标题、正文、话题、封面和配图。
- 使用专业化多 Agent 分工协作。
- 所有内容进入本地审核中心，支持批量预览、修改和审核。
- 已批准内容进入发布队列，由系统通过 MCP 执行经授权的单篇发布操作。
- 发布频率必须符合平台规则和账号实际状态，不得为了完成数量目标绕过限制。
- 每日根据真实运营数据复盘，改进选题、标题、视觉风格和内容方向。

技术优先级：真实可运行 > 内容质量 > 稳定性 > 自动化程度 > 功能数量。

请不要停留在方案设计阶段，必须实际创建项目、编写代码、安装可安装的依赖、运行测试并交付可使用的环境。

## 第三阶段：选题研究 Agent

开发 Topic Research Agent。

这是系统最重要的 Agent。

### 研究来源

1. 小红书关键词搜索结果。
2. 小红书推荐列表。
3. 热门笔记详情及评论。
4. 已配置的新闻或搜索服务。
5. RSS 订阅。
6. GitHub 开源热门项目。
7. 我授权导入的本地项目资料。
8. 我上传的照片、旅行记录和真实测评素材。
9. 系统已有笔记的历史运营数据。

禁止把没有公开来源验证的传闻当成新闻。

禁止未经授权大规模抓取或盗用其他博主素材。

### 内容分类

允许后台配置多个内容赛道：

A. AI 与开发技术
B. Codex / MCP / Agent 实战
C. AI 创业与副业
D. 旅游攻略与摄影
E. 家居生活与消费测评
F. 数码产品和穿搭
G. 社会热点与互联网锐评
H. 投资与量化研究科普
I. 其他发现具有增长潜力的新领域

初期不要简单平均分配流量，而是围绕账号定位设置核心领域与探索领域。

### 研究流程

每天收集至少 100 个原始选题候选。

针对每个选题分析：

- 热度与增长趋势
- 目标受众
- 用户搜索意图
- 用户痛点
- 内容时效性
- 相同内容的竞争程度
- 是否存在尚未被充分回答的问题
- 能否提供真实独特价值
- 是否有适合制作图文的素材
- 对当前账号的适配程度

对热门笔记分析标题结构、封面表现、评论诉求和内容切入角度。

不可照搬他人的文案或图片。

记录候选选题的证据来源、获取时间和可信度。

### 选题评分

满分 100 分：

- 热度与趋势：20
- 用户需求强度：20
- 差异化与原创价值：20
- 与账号定位的匹配：15
- 点击吸引力：10
- 收藏与传播价值：10
- 素材可得性：5

高分进入优先创作池。

缺乏可靠事实依据或者侵权风险高的选题直接拒绝，不允许通过高热度抵消这些问题。

- 哪些话题不值得投入生产资源？

7. 内容风格
8. 配图需求
9. 选题来源

预测必须标注为模型估计，不得伪装成真实流量数据。

- 高信息密度干货

## 第五阶段：内容创作 Agent

开发 Content Writer Agent。

输入是经过审核的选题规划。

输出至少包括：

- 3 个候选标题
- 最终标题
- 完整正文
- 话题标签
- 封面主标题
- 配图内容分镜
- 评论区讨论引导
- 引用来源
- AI 辅助创作标记
- 内容风险检查结果

### 内容要求

1. 标题必须简洁、有吸引力，同时真实反映正文。
2. 默认遵守小红书标题 20 字以内、正文 1000 字以内的限制，并以实际发布接口校验为准。
3. 开头快速突出用户收益、问题或者观点。
4. 正文需要有具体信息，不能全是空洞观点。
5. 鼓励独立判断，但区分事实、推测与个人观点。
6. 不允许伪造用户体验、旅游经历、消费记录、收益记录。
7. 禁止复制其他博主文章。
8. 禁止虚假夸张标题。
9. 避免明显的重复 AI 套话。
10. 必须根据平台要求正确标识 AI 生成或辅助内容。
11. 投资内容不允许保证收益或伪造历史回测成绩。
12. 对争议性事件，必须核对发布时间与至少一个可靠的原始信息来源，重要争议尽量交叉验证。

### 质量目标

文章应该做到：

有价值、有观点、有细节、有可读性，并且适合目标受众。

不要为了凑够每日 50 篇而制造低质量内容。

若当日高质量候选不足，应如实记录缺口，不得自动填充相似文章。

## 第六阶段：视觉设计 Agent

开发 Visual Designer Agent。

我希望系统自动完成小红书图文制作，不需要每天手动打开设计软件。

支持以下图文模板：

- 杂志封面型
- 极简高级感
- 数据图表型
- 旅行摄影型
- 对比测评型
- 攻略信息卡
- 热点观点型
- 数码科技型
- 生活方式型

每篇笔记优先输出：

1 张封面 + 2 至 5 张内容图。

特殊场景可以由编辑策略调整图片数量。

### 视觉要求

- 默认制作适合小红书的 3:4 竖版图片，例如 1080×1440。
- 图片文字必须清楚可读。
- 统一账号视觉识别，但允许不同内容类型有不同风格。
- 支持中文字体。
- 可使用我的原创照片、原创截图、生成的信息图。
- 对无版权授权的网络图片不得直接搬运。
- 使用 AI 合成的事实性场景应明确标为示意，不得冒充现场照片。
- 支持局部重新生成封面，而不必重写整篇笔记。
- 输出图片绝对路径，确保 MCP 可以读取。

### 图片生产方式

优先级：

1. 用户授权提供的真实素材
2. 程序生成的原创信息图和卡片
3. 有明确使用许可的素材
4. 经过标识的 AI 生成视觉素材

任何图片都要记录来源、版权状态和文件哈希。

## 第七阶段：质量审核 Agent

开发 Quality Reviewer Agent。

任何笔记进入发布池前，都必须执行自动质量检查。

评分维度：

- 标题吸引力
- 内容原创性
- 事实准确性
- 信息密度
- 图片清晰度
- 标题与图片一致性
- 账号定位匹配度
- 重复度
- 版权与合规风险

总分 100。

默认 80 分以上才能进入人工审核队列。

低于标准的内容允许进行一次自动改写，仍不合格则退回选题池。

实现跨历史内容的文本相似度检测、图片哈希检测和同主题去重，避免重复发帖。

质量评分必须保留具体理由，不能只给出一个数字。

所有事实性结论应能追溯到来源或真实项目资料。

## 第九阶段：发布 Agent

开发 Publishing Agent。

只使用已经确认可用的 xiaohongshu-mcp 功能发布图文。

调用前进行：

- 登录检查
- 内容审批状态检查
- 内容完整性检查
- 图片文件检查
- 当前账号状态检查
- 发布配额检查
- 同内容重复提交检查

### 发布策略

系统的内容生产目标是每天 50 篇。

发布能力应支持配置每日上限，但实际公开发布数量由平台允许的范围、账号状态及人工决策决定。

新账号默认低频运行并观察真实反馈。

禁止使用自动脚本大规模灌水、批量营销、规避风控或者模拟用户互动。

每篇公开发布都必须具有用户批准记录和明确的执行授权。

对于已经授权的单篇发布：

- 支持立即执行
- 在实际接口支持的范围内进行定时发布
- 采用串行队列
- 严格防止重复提交
- 保留请求记录
- 保存响应与发布时间
- 尝试核实发布结果
- 无法确认成功时进入 VERIFY_REQUIRED

如果出现验证码、异常登录、频率限制、风控提示或接口不确定状态，应暂停执行并要求人工处理。

禁止无限重试。

不得通过变更 IP、使用其他账号或调整浏览器指纹绕过限制。

### 定时说明

当前仓库公开文档中的 `schedule_at` 支持提前 1 小时至 14 天。

不得自行假设可以直接创建平台草稿。

对于未发布内容，优先保存在本地系统的草稿库。
